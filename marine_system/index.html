설계 결정 — 무엇을 정했고 왜

결정이유 · 근거
원본부터 저장, 가공은 그다음raw/ 에 기간별 원본을 남기면 규칙이 바뀌어도 다시 가공할 수 있다. 받은 기간은 건너뛰어 끊겨도 이어 받는다.
긴 기간은 date_chunks 로 나눠 받기한 번에 30일을 받으면 시간 초과 · 한도 초과에 한 번에 모두 잃는다.
일시적 실패만 재시도 (2초 · 4초)시간 초과 · 5xx 만 지수 백오프. 401 · 403 · 키 오류는 즉시 실패 — 재시도로 키 문제를 가리지 않는다.
의심값은 지우지 않고 flagok · missing · out_of_range · spike · maintenance. 판단은 저장 · 모델 단계가 한다.
JOBS 목록 하나를 모두가 본다CLI · run all · 스케줄러가 같은 함수를 부른다 → 수동 실행 = 자동 실행.
키는 서비스마다 · 코드 밖에NIFS_KEY_RISA · COO · REDTIDE · JELLY, DATA_GO_KR_KEY, KMA_AUTH_KEY — .env 환경 변수로만.
교차 검증은 가까운 관측소 · 하루 평균하버사인 최근접 짝짓기. 공공데이터포털이 '관측소 × 하루' 요청이라 시각이 아닌 하루 평균으로 비교.

보간은 마트에만 · 짧은 빈칸만연속 2일 이하 · 앞뒤가 있는 안쪽만 선형 보간, is_interpolated = 1. 외삽 금지.

설계 결정 — 무엇을 정했고 왜

결정이유 · 근거
출처가 달라도 '문서' 하나의 모양doc_id · kind · title · text · meta. 종류별 자연스러운 경계로 청킹(꼬리표 · 조문 · 제목) + embed_text 제목표.
시험지를 먼저 만든다평가 질문마다 정답 chunk_id · 핵심어, '자료에 없는 질문'도 넣는다 → Hit@k · MRR 로 채점.
검색기는 재서 고른다e5 가 TF-IDF 에 졌고(0.33 vs 0.42), RRF 는 '합의한 오답'으로 BM25 에 졌다. 가장 큰 효과는 질의 확장.
LLM 은 chat() 하나로 감싼다LLM_BACKEND 한 줄로 교체. 같은 시험지로 4종 비교 — 키 없으면 503 + 고칠 말.
근거 · 검사 결과 · 시간을 응답에AskOut = answer · sources · check(cite_ok · made_up · said_unknown) · live · seconds.
실시간 수온은 '있으면 좋은 것'마트가 꺼져도 200 · live=[] — 문서로만 답한다.
스트리밍(NDJSON) 필수CPU 에서 답 하나 17.5초 → sources → token → done 순서로 흘린다.
기록은 자바 서비스로모델 · 프롬프트는 자주 바뀌고(파이썬), 기록 · 피드백 · 통계는 안정적으로(Spring · 트랜잭션).

설계 결정 — 무엇을 정했고 왜

결정이유 · 근거
어장 = 권역 (위판장이 있는 항구 근처 바다)위판 자료에는 '어디서 잡혔나'가 없다 — 대리 지표와 한계를 기획서에 쓴다.
품목은 이름이 정확히 같은 것만삼치류 · 잿방어 · 고등어류 등은 뺀다 (58만 건 중).
위판은 며칠에 걸쳐 채워진다최근 7일은 매일 다시 받고, 기본키 + ON DUPLICATE KEY UPDATE 로 덮는다.
라벨 = 평소(28일 중앙값) × 1.5 × 요일 보정판단할 수 없는 날(일요일 · 평소 모름 · 돌풍)은 0 이 아니라 NaN. 보정값은 학습 구간에서만.
특성은 어제까지 + 오늘 달력D−1 까지의 위판 · 관측, log1p 로 눈금. 7일 평균 창 위치 하나로 AUC 0.814 → 0.886(누수).
평가는 순위로 — 주 지표 P@3무작위 · 규칙부터, 0.01 차이는 부트스트랩 95% 구간으로 판단.
고르는 규칙을 먼저 정하고 test 를 연다규칙을 확실히 이기는 모델이 없으면 가장 단순 · 안정한 로지스틱 (계수로 설명).
예보는 특성보다 경고로해상예보 풍속 ≥ 14m/s → warnings. 철이 아님 · 작은 권역 → excluded 에 이유.
